# 標準開發工作流程（8 階段）

互動式視覺化應用的標準流程分為 8 階段。這個 skill 讓你自動化「AI 高適合度」的環節，把「需求釐清」與「美學決策」保留給人 —— 形成人機協作。

```
需求釐清 → 資料準備 → 視覺設計 → 技術選型 → 元件實作 → 整合測試 → 部署發布 → 維護迭代
   ①          ②          ③          ④          ⑤          ⑥          ⑦          ⑧
```

## 各階段：目的、做法、產出、AI 適合度

| 階段 | AI 適合度 | 你要做的事 |
|---|:---:|---|
| ① 需求釐清 | 🔴 低 | 確認關鍵訊息、讀者、互動需求。**須與人協作確認意圖**；你可草擬規格，但別自己拍板意圖。產出：內容規格 (content spec)。 |
| ② 資料準備 | 🟢 高 | 實際讀檔，清理/彙整，檢視欄位型態、缺失值、分布。**一律靠執行得到，別猜**。產出：清理後資料 + 資料摘要。 |
| ③ 視覺設計 | 🟡 中 | 依資料型態對應合適圖表、版面、配色、互動。**先用 Layout picker 選版面**（見下節），再挑圖表。**美學決策由人把關**；你提建議。產出：版面選定 + 圖表選型 + 低保真原型。 |
| ④ 技術選型 | 🟡 中 | 依互動複雜度選框架（Chart.js vs D3.js），定義資料流。產出：技術架構。 |
| ⑤ 元件實作 | 🟢 高 | **AI 核心發揮處**：產出視覺元件、互動回呼、資料串接，**套用統一樣式字典**。產出：可運作前端元件。 |
| ⑥ 整合測試 | 🟢 高 | 撰寫測試、執行、依錯誤訊息修正。產出：通過驗證的整合版本。見 `verification.md`。 |
| ⑦ 部署發布 | 🟡 中 | 產生佈署設定，**敏感操作須人工核可**。產出：可存取的應用。 |
| ⑧ 維護迭代 | 🟢 高 | 依回饋自動修改、重構、優化。產出：更新版本。 |

## 各階段主要負責角色（人機協作對照）

| 階段 | 主要負責角色 |
|---|---|
| ① 需求釐清 | 產品負責人、領域專家 |
| ② 資料準備 | 資料工程師、分析師 |
| ③ 視覺設計 | UX/視覺設計師、領域專家 |
| ④ 技術選型 | 技術主管、前端工程師 |
| ⑤ 元件實作 | 前端工程師 |
| ⑥ 整合測試 | 前端工程師、QA |
| ⑦ 部署發布 | DevOps |
| ⑧ 維護迭代 | 全體團隊 |

## ③ 視覺設計：用 Layout picker 選版面

③ 視覺設計階段，**先選版面再寫 domain code**（低保真原型的核心）：

1. 讀 `references/layout-options.md`，依使用者的資料形狀從 9 種版面挑 **3–4 種**候選（別列滿九種，會造成選擇癱瘓）。
2. 複製 `assets/layout-picker-template.html`，替換 `{{PROJECT_NAME}}`、刪掉未提供的卡片、把示意標籤改成使用者實體。
3. 用 **Artifact 工具**發布成頁面，請使用者在對話中回覆選定的版面代號（可附微調，如「B，但把篩選器放最上面」）。點卡片只做視覺標記，頁面無法把選擇傳回。
4. 據選定版面搭前端。**無 Artifact 工具時** fallback 到 `AskUserQuestion` + ASCII wireframe 呈現候選。

版面的四大設計原則（即時 hover 回饋 / 漸進揭露 / 捲動保護 / 顏色留給資料）見 `layout-options.md`；hover 回饋的實作驗證見 `verification.md` 互動層，避免重複。

## 用 scaffold 開新專案

⑤ 元件實作前，可用 `scripts/scaffold.py` **一鍵生成套方向 A 雙主題的專案骨架**，取代每次手搭：

```
python scripts/scaffold.py <name> [--fullstack] [--charts d3|chartjs|recharts] [--js] [--entity <e>] [--port <p>]
```

- **預設純前端**：Vite + React + TS + Tailwind v4，專案根即前端。
- **`--fullstack`**：另加 FastAPI + SQLAlchemy 2.x + SQLite + Pydantic v2 後端（`/api/health`、`routers/<entity>s`、seed）與 Vite dev proxy（`/api` → `localhost:<port>`）。
- **`--charts`**：範例圖用 `d3`（預設）/ `chartjs` / `recharts`；顏色一律從複製進來的 `styleDictionary.js` 讀，不寫死。
- 生成後照兩階段設計（內容/樣式分離）把 `ExampleChart` 換成 domain 圖表，並跑 `references/verification.md` 的五層驗證。

## 結論：你應聚焦的四個環節

編程代理應聚焦 **② 資料處理、⑤ 元件實作、⑥ 整合測試、⑧ 維護迭代**（AI 高適合度），把 **① 需求釐清**與 **③ 美學決策**留給人確認。這不是能力限制，而是分工：意圖與美感需要人的脈絡，其餘的重複性工程工作交給你自動完成並用執行來驗證。
