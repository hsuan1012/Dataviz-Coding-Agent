# 版面選項 catalog（9 種標準版面）

資料視覺化 app 的 9 種標準版面，供 workflow 的「Layout picker」步驟使用（見 `workflow.md` ③ 視覺設計階段，通常在 `scripts/scaffold.py` 生成通用骨架**之後**、寫任何 domain code **之前**）。picker 頁面本身在 `assets/layout-picker-template.html`：改造後發成 Artifact，讓使用者**先選版面結構，再開始客製**。

## 九種版面

| Key | 名稱 | 結構 | 適用 | 取捨 |
|-----|------|------|------|------|
| A | 側欄 + 圖表格 | 左側導覽列；右側等重的 2×2（或更大）圖表格 | 4 種以上同等重要的指標；多頁應用 | 沒有單一焦點 |
| B | KPI 條 + 主圖 | 上方一排統計卡；下方一張主導的時間序列圖；旁邊小輔助圖 | 有明確主指標 + 輔助細節 | 沒有天然「主指標」時效果弱 |
| C | 控制面板 + 焦點圖 | 篩選器/選項在左側面板；右側一張大圖獨佔版面 | 單一張可深度探索、控制項多的圖 | 跨視圖比較要靠點擊切換 |
| D | 敘事捲動報告 | 單欄敘事，文字與滿版圖表交錯（scrollytelling 變體：固定圖表 + 捲動驅動故事） | 對外說明發現 | 非監控工具；純文字版互動性低 |
| E | 分頁視圖 | 上方分頁，一個主題一頁，各自獨佔整個畫布 | 同一份資料下好幾個獨立問題 | 無法同時看兩個視圖 |
| F | 分割比較 | 左右兩個對稱面板、座標軸同步 | 「A 對 B」的比較（區域、年份、情境） | 超過兩個對象就不順手 |
| G | 主從清單 | 左側可選清單/表格；右側顯示選中列的統計與圖表 | 逐一檢視大量同類實體（鄉鎮、產品、樣本） | 沒有一次總覽 |
| H | 小倍數牆 | 同一張圖依類別重複、共用座標軸 | 在多個群組間比較同一指標、掃視抓離群值 | 每格太小、放不下細節 |
| I | 地圖 + 明細欄 | 大幅地圖（或其他空間視圖）為主體；點區域後側欄顯示該區數字 | 本質上是地理資料 | 地理不是重點時版面浪費 |

### 個別版面注記

- **A + B 合起來就是「經典 BI dashboard」**（Tableau / Power BI 的樣式，多圖 app 最泛用的選擇）：全域篩選器放側欄或頂部控制列、一排帶趨勢箭頭的 KPI 卡、一張主圖、旁邊/下方數張輔助圖。使用者說「做個 dashboard」時，把這個 hybrid 當候選之一。它的關鍵是**連動視圖（linked views）**：在主圖選一個範圍或類別，會 cross-filter 其他輔助圖（把選取狀態拉到共用的 React state，每張圖都讀它）。**但不是每張輔助圖都該連動**——若某張圖的角色是「全域對照基準」（如不分篩選、恆常顯示全體排名/總覽的圖），刻意讓它**不**讀共用的篩選/選取 state，並在圖上明確標示「此為全域排名，不受篩選影響」，避免使用者誤解為連動失效。這個決定屬於①需求釐清階段：規格要**逐張圖**寫明它連動哪個 state（或明確聲明不連動），別預設「有共用 state 就全部都要接」。
- **D 有 scrollytelling 變體**（NYT 風的引導式互動資料故事）：主視覺**固定（sticky）**在中/右，隨讀者捲過各段敘事文字而轉場；在關鍵故事點浮出面板讓讀者自己拉 slider 調參數。當故事要被「體驗」而非只是被讀時，用這個變體取代純報告。
- **G 的主清單要資訊密集**，別做成空清單：加搜尋框、每列一條 sparkline、或用 treemap 當選擇器 —— 重點是快速挑目標。明細面板在選取當下就直接載入完整互動圖表，不要多一次點擊。

## 四大設計原則 —— 不論選哪個版面都適用

這四點會延續到 ③→⑤ 元件實作，與選定版面無關。**這四點與本 skill 既有的驗證/選型方法論是同一套事實來源，此處只列策展要點，實作與驗證細節交叉引用，不重複展開：**

1. **即時視覺回饋。** hover 顯示準確 tooltip、並高亮/放大所指的圖元。→ 互動層驗證（含 Playwright）見 `verification.md`。
2. **漸進揭露（progressive disclosure）。** 先給總覽，細節只在點擊、篩選或縮放時揭露；別一開場就是最細的視圖。
3. **響應式與捲動保護。** 圖表手勢在手機上會和頁面捲動衝突：小螢幕停用複雜的 drag/brush，退回點按互動或簡化的靜態圖。
4. **視覺簡潔、顏色留給資料。** 控制項（按鈕、篩選器、slider）維持中性 —— 用方向 A 的冷石板中性色（`themes.*.surface / border / textMuted`），把飽和色留給資料圖元與異常值。強調色（青綠 `accent`）只點互動元素，**不進數值色階**。→ 強調色 vs 數值色階的分離、色盲安全色階見 `chart-selection.md` 與 `assets/styleDictionary.js`。

> 配色一律走**方向 A 雙主題**（冷石板 + 青綠，深淺兩套），從 `assets/styleDictionary.js` 讀，**不採用**老師 dataviz-webapp 的白底標準色。

## 為專案策展 —— 只給 3–4 種，別列滿九種

一次列滿會造成選擇癱瘓。依使用者的資料形狀挑候選：

- **一條主線時間序列** → B，備選 C 或 E
- **大量相似實體**（表格的列） → G、H、A
- **地理 / 區域資料** → I，備選 G 與 H
- **明確比較問題**（「X 對 Y」） → F，備選 H
- **一份資料、深度互動探索** → C，備選 B
- **一份資料下好幾個不相關問題** → E，備選 A
- **交付物是書面/簡報** → D，備選 B
- **引導式互動資料故事** → D（scrollytelling 變體），備選 C
- **「像 Tableau / Power BI 的 dashboard」** → A+B hybrid（經典 BI dashboard），備選 E
- **一般 dashboard、沒有強訊號** → A、B、E

Hybrid 是常態也鼓勵 —— 使用者常回「B，但用 C 的篩選面板」。把選定版面當作框架，把要求的元素折進去。

## 使用 picker 模板

1. 複製 `assets/layout-picker-template.html`，替換 `{{PROJECT_NAME}}`，刪掉不提供的版面卡片（每張是自足的 `<button class="card">…</button>`，A 到 I）。
2. 便宜可做時，把示意標籤與統計卡數字改成使用者的實際實體，讓預覽像**他們的** app。
3. 用 Artifact 工具發布，請使用者在對話中回覆選擇（點卡片只做視覺標記，頁面無法把選擇傳回）。
4. 所有預覽走方向 A 雙主題配色（冷石板中性 + 青綠強調），隨主題深淺切換。

環境若無 Artifact 工具，fallback 到 `AskUserQuestion` + ASCII wireframe 呈現策展後的候選版面。
