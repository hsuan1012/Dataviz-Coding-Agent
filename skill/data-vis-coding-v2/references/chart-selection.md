# 圖表選型規則

選圖表是階段一「內容決策」的核心。原則：**先靠資料摘要得到每欄的型態，再依型態對應圖表**。型態必須靠實際讀檔推斷（number / date / string / geo），不要憑欄名猜數值分布。

## 選型規則（優先序，由上而下第一個命中者勝）

| # | 條件 | 建議圖表 | 說明 |
|---|---|---|---|
| 1 | 有地理欄位 + 數值欄位 | **choropleth（區域地圖）** | 例如「各縣市/鄉鎮人口」。Chart.js 無內建 → 用 D3.js。 |
| 2 | 有時間欄位 + 數值欄位 | **line（折線圖）** | 時間趨勢。 |
| 3 | 兩個以上數值欄位 | **scatter（散點圖）** | 兩數值關聯；加第三數值可做 bubble。 |
| 4 | 類別欄位 + 數值欄位 | **bar（長條圖）** | 類別比較，最通用的後備。 |
| 5 | 一個類別欄位佔比 | **pie（圓餅圖）** | 類別數少（≤6）且是「佔整體比例」時才用。 |
| 6 | 資訊不足 | **bar（取前兩欄）** | 保守後備，並主動向人確認。 |

規則命中後，仍要把選型當「建議」提給人；若內容規格已指定偏好圖表型態，以人的指定為準（保留欄位對應）。

## 地理欄位偵測（choropleth 的前提）

資料摘要通常只分 number/date/string，「地理性」要靠**欄名**判斷。命中以下任一即視為地理欄位：

- 英文（不分大小寫）：`city, country, region, state, province, county, nation, district, lat, lon, lng, latitude, longitude, geo, zip, postal`
- 中文關鍵字：`縣市、城市、國家、地區、縣、市、州、省、鄉鎮、區域、經度、緯度`

台灣鄉鎮人口這類資料，地理欄位常是「縣市」「鄉鎮市區」，值如「臺北市」「板橋區」。這類要做 choropleth，需要對應的邊界 **GeoJSON/TopoJSON**（鄉鎮界），把資料的行政區名對應到地圖的 feature 屬性。

## Choropleth 實作要點（實測歸納的坑）

1. **優先用「行政區代碼」join，而非名稱。** 邊界檔與統計資料若都帶行政區代碼（如 8 碼 TOWNCODE），以代碼比對可完全避開名稱不一致。只有當一方沒有代碼（例如政府統計只有 `site_id`＝縣市+鄉鎮全名）時，才退而用名稱。
2. **名稱 join 一定要正規化。** 政府資料多用「臺」，其他來源常用「台」；還有全形空白、行政區改制（頭份鎮→頭份市、鄉→區）。至少做 `臺→台`、去空白 再比對，並**列出未對上的鄉鎮、回報涵蓋率**（別假設 100%）。
3. **邊界與資料的年份／版本要對得上。** 舊版鄉鎮界（如 1982）用舊行政區（桃園縣、台中縣市分開），配現行人口會大量對不上；用現行版邊界（含六都改制）才會乾淨。
4. **離島要用 inset。** 金門、連江（馬祖）遠在西/北，若與本島同一投影會把本島擠小、左側一片空白。作法：主圖只涵蓋本島（含澎湖），金門/連江各自獨立投影塞進角落的小方框（加標籤與外框）。
5. **人口這種右偏資料用分位數(quantile)或門檻色階，別用線性。** 線性色階下多數鄉鎮會擠在最淺一格；`d3.scaleQuantile` 讓每一色階含相近數量的鄉鎮，中低人口區也分得出深淺。色碼仍取自 `styleDictionary.sequentialScale`。
6. **主島投影要 fit 到「固定地理視窗」，不要 fit 到 features 自身邊界。** 有些「本島」鄉鎮的幾何夾帶極遠的外島：高雄市**旗津區**含**東沙島／南沙太平島**（最南近赤道）、宜蘭縣**頭城鎮**含**釣魚台**（最東）。只靠縣名濾外島抓不到這種「主島鄉鎮夾帶遠島」，`projection.fitSize(features)` 會被撐爆把本島壓成一小塊。解法：`fitSize/fitExtent` 到一個**寫死的台灣本島經緯度框**（約 lon 119.3–122.1、lat 21.85–25.35），遠島自然落在畫布外被 SVG 裁掉。**症狀辨識**：本島縮很小且偏某一角、大片空白 → 先用 `d3.geoBounds(非離島FC)` 印邊界，若 lat/lon 跨度遠大於本島即中此坑。
7. **界定「範圍框」用 MultiPoint（四角點），不要用 Polygon。** d3 球面幾何看環繞方向（winding order）；手寫的 bbox Polygon 環序若反了，會被判讀成「地球其餘部分」，投影瞬間縮到極小（幾 px）。用 `{type:"MultiPoint",coordinates:[四角]}` 界定 fit 範圍沒有環序歧義。**單元測試的合成 feature 也會踩同一坑**：手寫正方形 Polygon 測 `geoBounds` 時外環必須順時針（平面直覺的逆時針會被判成「全球挖掉此塊」，bounds 變 ±180）。
8. **inset 投影用 `fitExtent`，不要用 `fitSize`。** `fitSize([w,h])` 只決定「縮放到多大」、一律把幾何擺在原點 (0,0)，島形會被畫到 SVG 左上角、與你在別處畫的方框/標籤**脫節**（框是空的、島跑到別的地方）。`fitExtent([[x0,y0],[x1,y1]], fc)` 同時吃「位置＋大小」，把島定位進框（上緣預留幾 px 給標籤）。主圖被 bug 蓋住時這個脫節常沒被發現，修好主圖才暴露。
9. **行政歸屬 ≠ 地理位置：不一致的離島要獨立 inset 或「fit 排除＋clip」。** 例：**烏坵鄉**行政上屬**金門縣**，地理卻遠在金門與馬祖之間。若把它和金門本島一起 `fitExtent`，會把整個金門群島壓到很小。兩種作法：(a) 從金門 inset 排除烏坵、另給獨立小框；(b) **fit 集合排除烏坵＋inset 群組加 `clipPath`**（超框內容裁掉；若 app 有下鑽，烏坵於下鑽金門縣視圖用自然邊界仍可見，README 註明即可）。inset 定義建議資料驅動（`{label, match(name)}` 陣列）方便增減。
10. **inset 框的「位置」必須通過與主圖投影內容的碰撞數據檢查，不可憑感覺挑。** 實測翻車案例：框放左側 y300–564「看起來空」，但主投影把**澎湖**放在 x87–183/y381–540——直接壓框，且**自動測試全過、審全頁截圖的 AI 肉眼也誤判成框旁的景**，靠人看局部截圖才抓到。作法：寫個 node 腳本，用與 app 相同的 fit 邏輯把主圖每個 feature 投影出 bbox，斷言「皆不與任何 inset 框重疊」，當常駐回歸跑。注意 **MultiPolygon 要拆成單一 polygon 逐一算 bounds**——旗津區整體 bbox 因南海島礁大到畫布外，會產生假陽性。
11. **下鑽（drill-down）時，指標不可加總就不要做上層聚合著色。** 票數、人口可加總 → 縣級著色成立；密度、平均所得、死亡率等**比率/平均型指標**做縣級平均有「未加權」誤導（參考站做法不能照搬）。誠實做法：下鑽＝縮放至該行政區（麵包屑＋返回），不發明上層數值；或有權重資料時先加總分子分母再算比率、並在 UI 標明口徑。

## 動態泡泡圖／跨年（時間序列）資料實作要點（實測歸納的坑）

做 Gapminder 式動態圖（x-y 隨時間播放）時，難點九成在「跨期資料對齊」，不在畫圖：

1. **跨年 join 前先正規化行政區改制，並硬檢核「每期實體集合完全相同」。** 升格改名
   （桃園縣→桃園市、員林鎮→員林市、頭份鎮→頭份市）會讓同一實體在不同年份用不同鍵，
   年增率在改制年整組斷裂或實體默默消失。統一正規化為**現行名**；檢核不過就列出差集停下來，
   別讓實體無聲蒸發。
2. **政府開放資料 CSV 有雜訊列，別假設 header 後全是資料。** 常見：第 2 列是中文欄名
   重複列、檔尾有註腳／空白列、缺值用「…」。資料列的判準用結構性條件（如「識別欄為
   純數字」）過濾，並把被排除的列印出來人工確認。
3. **識別欄格式同檔內都可能不一致。** 例：多數列是「縣市+鄉鎮」合併字串，但特殊列
   （東沙、南沙群島）沒有縣市前綴——對這類列記錄原字串即可，硬拆會拆出垃圾。
4. **衍生欄位做自洽檢核。** 資料若同時給 population、area、density，驗 density ≈
   population/area（容差內）——這是免費的資料錯置偵測器。
5. **聚合層級的比率「先加總再算」。** 縣市密度＝總人口÷總面積、縣市年增率＝先加總
   人口再算增率；把下層比率平均起來是錯的。寫一個會抓到「平均 bug」的測試
   （用一組平均值≠重算值的假資料）。
6. **年增率的三個邊界**：首期無前值不產點、期別不連續跳過、前值 ≤ 0 防除零。
7. **動畫軸域用全期資料一次算定**，逐期重算會跳軸；D3 data join 以實體鍵
   （名稱/代碼）當 key，過渡動畫才會是「同一顆泡泡在移動」而不是換一批圓。

## 階層圖（treemap / sunburst）實作要點（實測歸納的坑）

treemap 與 sunburst 用的是同一份階層資料（parent→children 巢狀），差別只在 layout；
一次做兩種時共用資料層、狀態與前處理，成本幾乎只多一個元件：

1. **頂層只畫「目前根節點的直接子層」，下鑽才展開下一層。** 全部葉節點（如 368 鄉鎮）
   同屏會讓小實體面積/弧角趨近 0——看不見也點不到。預設畫第一層（22 縣市），
   點擊下鑽該分支、breadcrumb 返回；treemap 與 sunburst 用同一策略與**同一份下鑽狀態**，
   切檢視不重置。
2. **共用前處理抽成 lib 純函式。**「淺複製根節點、剝掉孫層、sum(人口)、sort(由大到小)」
   這段 treemap（`d3.treemap`）與 sunburst（`d3.partition`）完全相同，放兩個元件內
   會逐字重複且無單元測試；抽成 `layoutHierarchy(root)` 進 lib（可 vitest 直測，
   記得驗「不改動原始資料」）。
3. **標籤三規則**：(a) 面積/弧角低於門檻不畫標籤，數值靠 tooltip；(b) sunburst 細弧
   標籤要**沿半徑方向旋轉**（左半圓翻 180° 保持朝上），水平標籤在相鄰細弧必互撞；
   (c) 標籤顏色依**填色深淺切換**（樣式字典給 labelLight/labelDark 一對 token），
   一律深字會在色階最深兩級上變不可讀（對比 1.4:1）。
4. **色階跨年定軸：分位點由後端/資料層一次算好下發。** quantile 切點用全期全實體
   算一次、跨年固定，前端只做映射——否則前端得先抓全部年度才能定軸。
5. **圖例文案必須與分級邏輯一致。** 分級用 `>=` 切點（半開區間 [下界, 上界)）時，
   圖例寫「X 以上，未滿 Y」；別把浮點切點四捨五入再 -1 做成整數區間，
   切點附近會出現顏色與圖例矛盾（v2 的「整數不重疊區間」教訓只適用整數切點）。
6. **tooltip 顯示「佔上層比例」**（node/parent 人口比）是階層圖最有價值的一行資訊，
   驗證時抽查它＝下鑽正確性的免費檢核。

## 流量/轉移圖（sankey / chord / heatmap / waterfall）實作要點（實測歸納的坑）

sankey、chord、heatmap 三者可共用**同一份 OD（起訖）矩陣**；waterfall 用
「存量增減分解」資料——同一資料來源家族可一次做完四種圖：

1. **動工前先掃描資料可得性。**「資料集存在」≠「期別齊全」：政府開放資料常有
   月份缺洞（實測某遷徙資料集 13 個月裡只開放 6 個月）、同主題有新舊版資料集
   （動態統計 ODRP003→012→061 三代），要逐期 PAGE=1 探測後**由實測結果決定
   時間範圍**、挑覆蓋完整的後繼版資料集，別按文件宣稱規劃。
2. **OD 矩陣排除對角**（同實體內部流動通常大於跨實體流，會壓縮色階/佈局），
   並硬檢核「每期 n×(n-1) 組合齊全、無負值」。
3. **sankey 的 462 條流全畫會糊**：取 top-N（如 40）並在圖上**註明涵蓋率**
   （lib 純函式算，含全零防除零）；左右同名實體各建節點（`o:`/`d:` 前綴）。
4. **chord**：標籤沿半徑旋轉（左半圓翻 180°）；hover 實體弧聚焦（其餘 ribbon
   降 opacity）比全部常亮可讀得多。
5. **heatmap**：對角格用中性色明確標示「不適用」；45° 旋轉的欄標籤會超出
   最後一欄，viewBox 要預留右緣（實測 +48px），截圖驗收時逐緣檢查裁切。
6. **waterfall**：累計區間（y0,y1）算法抽 lib 純函式（含負淨增減案例的測試）；
   y 軸不從 0 起算才看得見增減段，但**圖上必須註明**；把「分解期末 ≠ 實際期末」
   的 mismatch 檢核**做進 UI 顯示警告**——資料錯置會直接被使用者看見。
7. **多期間共用檢視的狀態**：合計與單月的值域差好幾倍，**各自算 quantile 尺**；
   期間顯示文字由資料推導（年份從期別字串取，勿寫死）；重複分位切點（大量並列
   小值時會發生）對應的空級距，圖例要跳過，否則出現「X 以上，未滿 X」矛盾項。

## 分布圖（ridgeline plot）實作要點（實測歸納的坑）

「多組別 × 同一數值變數的分布」（如 12 個月份 × 全域網格溫度）用 ridgeline：
各組一條 KDE 密度曲線、共用 x 軸、垂直堆疊部分重疊（OVERLAP ~1.9 倍列高）。

1. **KDE 先分箱再捲核**：逐點 kernel 是 O(n×ticks)，上萬點 × 多組會卡；先把值分箱
   （箱寬=資料粒度,如 0.1）再對箱心做 Epanechnikov，複雜度降到 O(bins×ticks)，
   結果對箱寬粒度等價。KDE 抽 lib 純函式配測試：密度積分≈1、峰位、**雙峰保留**
   （bandwidth 別大到抹平多峰——山區/平地雙峰正是這種圖的資訊所在）、空資料回全零。
2. **x 域與色階域用全期固定 domain**（跨期切換才可比），逐條 ridge 依該組統計量
   （如中位數）從數值色階取填色——與主圖（地圖/heatmap）同一把色階尺，兩圖視覺互證。
3. **跨期切換的形狀 morph**：path `d` 不能 CSS 動畫。xs 取樣網格固定 → 前後路徑點數
   一致 → `d3.transition().attrTween('d', () => interpolateString(from, to))` 可直接補間
   （~520ms easeCubicInOut）；**`d` 不經 React 控制**（初次與動畫都由 effect 以 DOM API 設定，
   否則 re-render 會打斷動畫），fill 走 CSS transition 即可。
4. 當前組高亮（accent 描邊+提高 opacity）、點 ridge 跳至該組；子集合過濾（如選取某縣市）
   時 KDE 對子集重算,morph 動畫同樣適用。

## 進階圖形（計畫書列的可能類別）

依資料與目的，可能用到：dynamic scatter/bubble（含時間軸）、choropleth map、treemap、sunburst、waterfall、sankey、chord diagram、heatmap。這些多數要 D3.js。表現形式可整合為 **dashboard**（多圖連動）。

## 決策提示

- 「比較大小」→ bar；「隨時間變化」→ line；「兩變數關係」→ scatter；「地理分布」→ choropleth；「層級佔比」→ treemap/sunburst；「流量/轉移」→ sankey；「相關矩陣」→ heatmap。
- 類別太多（>12）的 bar 考慮排序取 top-N 或改用其他呈現，別硬塞。
- 不確定時，做一個低保真原型讓人看版面與互動，再定案。

## 設計系統套用要點（方向 A）

- 強調色與數值色階「分離」：強調色（青綠）只用於按鈕／作用中 tab／連結／重點；數值一律走 quantile 色階。
- **強調色若恰好撞上分類色階（如洲別/區域）裡的某一色，選取／hover 外框要換色，不能沿用強調色**：兩個獨立專案都實測踩過同一個坑——地圖/散布圖用青綠當強調色（選取外框、作用中按鈕），但同一畫面另有一組洲別/區域分類色階，其中一色恰好也是青綠系（如歐洲＝青綠、「中」區域＝青綠）。選取外框沿用強調色時，選中「該分類剛好是青綠」的項目＝外框整個融進底色，肉眼幾乎看不出被選取（其他分類選中時外框正常可見，這種「只有特定資料值才會壞」的視覺 bug 尤其容易在測試裡漏掉，因為預設情境未必踩到那個分類）。**解法**：選取／hover 外框改用一個跟整組分類色階都對比明顯的獨立色（如粉紅 `#DB2777`／深色模式 `#F472B6`），不要跟任何語意色階共用，深淺主題各自對比皆需檢查。判斷「會不會撞色」不能只看預設截圖，要逐一切到每個分類色實際選取一次比對。
- sequential 色階單一色相、單調（亮度嚴格遞增或遞減）、無紅 → 色盲安全；choropleth／treemap／heatmap 共用同一 quantileScale。
- **類別數遠超 categoricalPalette（如 20+ 個縣市/國家）時，改用 LCH 程序化配色，別讓 8 色循環撞色**
  （指導老師調色盤 app 的方法，treemap dogfood 實證）：`d3.hcl(hue, chroma, L)`——
  ①各類別在色相環均分（`hue = index×360/N`，index 用穩定鍵如行政代碼，改名/跨年不變色）；
  ②階層圖再用「同色相×明度階」表達內層（群組標題帶較深 L、葉子循環 2–3 段 L，
  即色彩矩陣的「同欄不同列」）；③彩度是鮮豔度的單一旋鈕——預設 ~45 偏鮮豔，
  使用者嫌刺眼時降到 ~30（柔和）一次到位，色相/明暗結構不動；
  ④參數收進 styleDictionary 當 token（深色主題彩度略降、明度整組下移），不要散在元件裡。
- **冷暖語意資料（溫度等）是「數值色階無紅」規則的語意例外**：氣象慣例冷藍→熱紅
  比單色相直覺得多。仍用 LCH 方法生成（每個 stop 寫成 `hcl(h, c, L)` 參數、逐點過
  `displayable()` 色域檢查、生成腳本進 repo 可稽核）：色相路徑「藍 h~265 → 中央 →
  紅 h~35」**中央 stop 要壓低彩度**（避免插值掃過綠色帶）；深藍在低明度下色域上限
  很低（L40 時 c>45 就出界），出界就降 c 或提 L。**使用者說色階「太淡/太透明」時，
  第一嫌犯是中段明度不是彩度**——L84+ 的淡色中段才是「淡」感主因（實測 chroma +14
  仍被嫌淡，中段 L 88→76 一次到位）；兩主題各調一組（深色版整組壓亮度）。
- **比值衍生色階（生師比、人均值等「大小÷大小」的第二變數）用「分位數夾擠」定義域**
  （treemap 明度=生師比 dogfood 實證）：①定義域取當年/當期**最細層級全體**的
  p10–p90 分位數再線性 clamp——用 min/max 會被小樣本離群值（如 8 人小校）撐爆整把尺；
  ②聚合層級（鄉鎮/縣市）的比值必然落在葉子極值之間 → 跨層級同一把尺可比，
  下鑽時顏色語意不變；③除零（分母 0）明確定義端點值（如「無教師=最深端」），
  別讓 NaN 掉進色階；④切期間要重算定義域；⑤圖上必須放一行圖例文字說明深淺方向
  （「色淺＝比值低」），顏色編碼第二變數不自我解釋。
- **競速長條圖（bar chart race）在 HTML 清單就做得出來，不必上 d3 join**：
  列=絕對定位（`top = 名次×列高`）＋長條=背景 `width %`，兩者掛同一段 CSS transition
  （~550ms），**key 用穩定識別（代碼），換期間時 React 重排 top → FLIP 名次追逐動畫**；
  排序必須是量值排名（地理/字母排序下名次不動，就不是 race）；長條色可沿用
  類別色相（如所屬縣市 LCH 色）降 opacity 墊在文字下，窄側欄也放得下。
- treemap/sunburst 標籤字色：依填色實際亮度算 WCAG 對比、取對比較高者（非固定 index 門檻），深淺主題皆正確。
- 中間色調對純黑/白皆難達 AA 4.5 時，標籤加「對比描邊（halo）」：描邊色 = 與文字相反的標籤色，文字對描邊 ~21:1，任何填色都可讀。
- sunburst 過細弧段不硬塞旋轉字（門檻 ~0.12 rad），改靠 tooltip。
